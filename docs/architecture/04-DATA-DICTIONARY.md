# 4. Data Dictionary

Derived from `packages/db/prisma/schema.prisma` and the SQL migrations. Prisma `String` maps to PostgreSQL `TEXT`, `Int` to `INTEGER`, `DateTime` to `TIMESTAMP(3)`, `Float` to `DOUBLE PRECISION`, `Json` to `JSONB`, `@db.Date` to `DATE`. Identifiers are `cuid()` strings generated by Prisma. "DB rule" lists constraints that exist only in SQL migrations.

## 4.10 `AiAnalysis`

One row per analysis *attempt*. The API serves the latest attempt for a ticket.

| Column | Type | Null | Key / constraint | Description |
| --- | --- | --- | --- | --- |
| `id` | text | no | **PK** | |
| `ticketId` | text | no | **FK → Ticket.id**, `CASCADE`; indexes `(ticketId, createdAt, id)`, partial unique `(ticketId) WHERE status='PENDING'` | |
| `status` | `AiAnalysisStatus` | no | default `PENDING`; index `(status, createdAt)` | |
| `model` | text | yes | – | Provider model id(s) actually used (≤ 120 chars); kept on `FAILED` rows that were billed |
| `promptVersion` | text | no | – | e.g. `<KB_VERSION>/classify-v1/draft-v1` |
| `category` | `TicketCategory` | yes | state check | Result column |
| `priority` | `TicketPriority` | yes | state check | Result column |
| `confidence` | double | yes | DB rule 0 ≤ x ≤ 1 | |
| `rationale` | text | yes | state check | |
| `draftResponse` | text | yes | state check | Suggestion for an admin; not a message |
| `citations` | jsonb | yes | state check: array on `COMPLETED`, SQL `NULL` otherwise | Knowledge-base chunk ids |
| `inputTokens`, `outputTokens` | integer | yes | – | Provider-reported |
| `costMicrounits` | integer | yes | – | Millionths of a USD; `NULL` when the provider reported no cost (never 0 for unknown) |
| `errorCode` | text | yes | state check | Safe code, e.g. `AI_TIMEOUT`; set only on `FAILED` |
| `createdAt` | timestamp(3) | no | default `now()` | |

`AiAnalysis_state_check`: `PENDING` → all result columns and `errorCode` null; `COMPLETED` → category, priority, confidence, rationale, draftResponse and a JSON-array `citations` present, `errorCode` null; `FAILED` → result columns null, non-blank `errorCode`. `requiresHumanReview` is **not stored**; the API always returns the literal `true`.

## 4.13 Triggers and functions (all in migrations)

| Trigger | Table / event | Rule |
| --- | --- | --- |
| `AuditLog_append_only` | `AuditLog` before `UPDATE`/`DELETE` | Reject, except `actorId` → `NULL` |
| `Ticket_book_author` | `Ticket` before `INSERT`/`UPDATE OF bookId, authorId` | Book must belong to the ticket's author |
| `Ticket_assignee_admin` | `Ticket` before `INSERT`/`UPDATE OF assigneeId` | Assignee must be `ADMIN` |
| `TicketAssignment_guard` | `TicketAssignment` before `INSERT`/`UPDATE` | Assigner and assignee must be `ADMIN`; history append-only |
| `InternalNote_guard` | `InternalNote` before `INSERT`/`UPDATE` | Author must be `ADMIN`; immutable |
| `TicketMessage_visibility` | `TicketMessage` before `INSERT` | `ADMIN`-visibility message requires an admin author |

The release audit independently counted 6 integrity triggers on the staging database.
